# CampusHub 开发计划

> 本文档定义所有需开发模块的完整方案和实施计划，按里程碑拆分。

## 文档作用

定义开发范围、模块方案、里程碑顺序和输出产物，作为开发执行的路线图。

> 引用场景：开发实施前阅读理解技术方案；项目经理跟踪进度；每个里程碑开始前确认前置条件。

## 1. 开发范围总览

| 模块 | 技术栈 | 职责 |
|------|--------|------|
| chb_reward_plugin | Ruby (Discourse Plugin) | 监听 Discourse 事件，转发到后端奖励引擎 |
| 核心后端服务 | Go + PostgreSQL | IdP + 积分账本 + 奖励引擎 + 集市 API + 管理后台 API |
| 集市前端 | Next.js | 商品浏览、交易、入驻申请 |
| 管理后台前端 | Next.js | 配置管理、审核操作、监控面板 |
| OAuth2 授权页 | Next.js | 授权同意页、Token 交换 |

**Discourse 已有（无需开发）**：用户注册/登录、发布/回复、点赞、信任等级、通知、搜索、反垃圾、管理面板、REST API、OAuth2 Provider、Webhook。

## 2. 里程碑

### P0: 基础设施搭建（1 天）✅ 已完成

创建项目目录结构，初始化 Go 项目、Next.js 项目和 Discourse 插件目录，配置 Docker Compose 开发环境（PostgreSQL + Redis），初始化 Git 仓库。

**输出**：项目结构、开发环境、Git 仓库。

### P1: 数据库设计与迁移（2 天）✅ 已完成

创建 8 组迁移文件（000001-000008，含 up + down），实现 16 个 Go 数据模型，实现迁移入口。

**前置条件**：P0 完成。
**输出**：迁移文件 + 数据模型 + 表结构验证。

### P2: 核心后端基础框架（2 天）✅ 已完成

实现配置加载、数据库连接、统一响应格式、错误码定义、中间件（auth/cors/rate_limit/logger）、主服务入口和健康检查路由。

**前置条件**：P1 完成。
**输出**：可运行的后端框架。

### P3: 积分账本（3 天）✅ 已完成

实现积分池、用户余额、交易流水 Repository 和 Service。核心接口：余额查询、积分扣减（含行级锁 + 乐观锁 + 幂等）、转账、释放阀、对账查询。初始化种子数据（公共池 5 亿、官方池 0）。

**前置条件**：P2 完成。
**输出**：账本模块 + 种子数据 + 单元测试。

### P4: 奖励引擎（3 天）✅ 已完成

实现奖励规则、每日配额、奖励日志 Repository 和 Service。奖励发放逻辑（冷却检查 + 上限检查 + 补全 + 系数计算 + 幂等）。初始化默认奖励规则和等级日上限。

**前置条件**：P3 完成。
**输出**：奖励引擎 + 种子数据 + 单元测试。

### P5: Discourse 插件（3 天）✅ 已完成

实现 plugin.rb 入口、事件处理器、API 客户端、事件序列化器。配置插件参数（后端 API 地址、API Key）。集成到 Discourse Docker 环境。

**前置条件**：P4 完成（奖励引擎 API 就绪）。
**输出**：插件代码 + 集成文档 + 事件转发测试。

### P6: OAuth2 IdP（3 天）✅ 已完成

实现应用、授权码、Token Repository。实现授权码流程、Token 发放/刷新/校验、Scope 定义和校验、最低等级拦截。

**前置条件**：P2 完成。
**输出**：IdP 模块 + 授权页模板 + 单元测试。

### P7: 集市 API（3 天）✅ 已完成

实现商品 CRUD、入驻申请 + 审核、下单交易（含积分扣减 + 手续费 + 幂等）。

**前置条件**：P3 完成。
**输出**：集市 API + 单元测试。

### P8: 管理后台 API（3 天）✅ 已完成

实现系统配置、审计日志 Service。实现奖励规则、等级上限、手续费、积分池监控、用户管理、集市审核、数据统计 API。

**前置条件**：P2、P4、P6、P7 完成。
**输出**：管理后台 API + 审计日志模块。

### P9-P11: 前端开发（5/5/2 天）✅ 已完成

**P9 集市前端**：商品列表、详情、入驻申请、我的商品、订单管理页面，集成 OAuth2 登录。
**P10 管理后台**：登录、仪表盘、奖励配置、等级配置、应用管理、集市审核、积分池监控、用户管理、系统配置、审计日志页面。
**P11 授权页**：授权同意页（展示 scope、等级检查）、回调页面。

**前置条件**：P7（集市）/ P8（管理后台）/ P6（授权页）完成。
**输出**：完整前端页面（当时 13 条路由，P15 新增首页后为 14 条，`npx next build` 全量构建通过）。

**P9-P11 开发过程中修复的问题**：
- 前端文件被 PowerShell 编码破坏（GBK 乱码、引号丢失），仅 `app/admin/page.tsx` 损坏，已用 apply_patch 重写修复，其余文件验证完好
- 后端 handler 直接序列化无 json tag 的 repository 模型，导致 API 返回 `Status`/`SellerID` 驼峰字段，与文档约定 snake_case 不符；已为全部被返回模型补齐 json tag，并新增 `assertSnakeCase` 测试固化契约
- 缺“我的商品”端点：service/repo 已有 `ListMyItems`/`ListItemsBySeller` 但未暴露路由，已新增 `GET /api/marketplace/items/mine`（注册在 `/items/:id` 之前）
- 应用创建不生成 client_id/client_secret：已补随机生成，创建响应一次性返回凭据（secret 不落入列表接口）
- OAuth 授权确认断点：`/api/oauth/app-info` 原为 stub，授权页跳转的 `/oauth/authorize/confirm` 路由不存在；已实现 `GetAppInfo`、`POST /api/oauth/authorize/confirm`（校验 client/redirect_uri/等级，发放授权码），前端改为 fetch confirm 后跳转
- `auth_codes.scopes` 为 JSONB 列但存了空格分隔字符串导致写入失败：已实现 `scopesToJSON`/`scopesFromJSON` 转换
- `TokenRequest` 缺 json tag 导致 token 交换参数绑定失败：已补齐
- 奖励引擎对首次活跃用户直接拒绝（user_balances 无记录）：已改为 get-or-create 自动建档（`reward_service.Grant` 与 `marketplace_service.CreateItem/CreateOrder`）
- 端到端验证通过：签到/发帖奖励 → 商品创建 → 管理审核 → 买家下单（手续费 10% 进官方池）→ 资金流向核对 → OAuth 授权码/Token/校验全链路

### P12: 签到功能（2 天）✅ 已完成

插件前端插入签到按钮，插件注册 /chb/checkin 路由代理到后端，后端 checkin 奖励发放 + 每日签到检测。

**前置条件**：P4 + P5 完成。

## 3. 后端项目结构

```
chb-backend/
|-- cmd/server/main.go
|-- cmd/migrate/main.go
|-- internal/
|   |-- config/config.go
|   |-- model/          # 16 个数据模型
|   |-- repository/     # 数据库操作
|   |-- service/        # 业务逻辑
|   |-- handler/        # HTTP 处理器
|   |-- middleware/     # 中间件
|   |-- idp/            # OAuth2 授权服务器
|-- pkg/errcode/        # 错误码
|-- pkg/response/       # 统一响应
|-- migrations/         # 8 组迁移文件
|-- config.yaml
|-- config.test.yaml    # 集成测试配置
|-- integration_test.go # 集成测试
|-- go.mod
```
