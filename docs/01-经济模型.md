# CampusHub 经济模型（CHB）

> 本文档定义 CHB（CampusHub Coin）积分体系的经济规则，是积分相关功能设计和开发的唯一参考。

## 文档作用

定义 CHB 积分池结构、获取与消耗规则、集市流转规则、手续费与释放机制，确保积分体系的总量恒定性、可审计性和防通胀设计。

> 引用场景：任何涉及积分变动（奖励、消费、转账、集市交易）的设计和开发；对账和审计；管理后台配置积分规则时核对经济约束。

## 1. 积分总量与池结构

### 1.1 总量约束

- **CHB 总供应量：5 亿（500,000,000）**，预设为公共积分池，总量恒定不可改变。
- **不支持充值或兑换法币**：CHB 只能通过论坛贡献行为和生态内流转获得。
- 积分池总量、公共池余额、官方池余额、用户余额之和在任何时刻必须满足守恒等式：

```
公共池余额 + 官方池余额 + 用户余额总和 = 总供应量（5 亿）
```

### 1.2 积分池

| 池 | 初始余额 | 来源 | 用途 |
|----|---------|------|------|
| 公共积分池 | 5 亿 | 预设 | 用户奖励发放来源 |
| 官方积分池 | 0 | 手续费收入 | 系统收益、释放阀操作 |

**核心约束**：
- 公共积分池与官方积分池相互隔绝，除释放阀操作外不允许互相转账。
- 用户积分获取一律从公共积分池支出；手续费一律进入官方积分池。

## 2. 积分获取（奖励引擎）

### 2.1 获取方式

用户通过论坛贡献行为获取 CHB：

| 行为 | 默认单次奖励 | 冷却时间 | 每日上限 | 幂等键规则 |
|------|------------|---------|---------|-----------|
| 发帖 | 100 CHB | 300 秒 | 500 CHB | `post_{ref_id}_{user_id}` |
| 回复 | 50 CHB | 60 秒 | 300 CHB | `reply_{ref_id}_{user_id}` |
| 签到 | 30 CHB | 86400 秒（每天一次） | 30 CHB | `checkin_{user_id}_{date}` |
| 被点赞 | 20 CHB | 无 | 200 CHB | `liked_{ref_id}_{user_id}` |

> 以上为默认值，管理后台可配置每次发放量、冷却时间、每日上限、启用状态。

### 2.2 信用等级与倍率

| 信用等级 | 每日获取上限 | 奖励倍率 |
|---------|------------|---------|
| TL0 | 100 | 0.50 |
| TL1 | 500 | 1.00 |
| TL2 | 1000 | 1.00 |
| TL3 | 2000 | 1.25 |
| TL4 | 5000 | 1.50 |

**每日重置时间：早晨 6:00（Asia/Shanghai）**。

**发放计算**：`实际奖励 = 规则奖励 × 等级倍率`，同时受用户每日上限和等级每日上限双重约束。

### 2.3 奖励发放约束

- **幂等性**：同一用户对同一内容（ref_type + ref_id）只能获得一次奖励，由 reward_logs 唯一索引 `(ref_type, ref_id, discourse_user_id)` 保证。
- **防刷**：冷却时间内重复行为不发放奖励；用户达到日上限后停止发放。
- **账户状态**：冻结账户不发放奖励。

## 3. 积分消耗

### 3.1 论坛内

论坛定位为知识共享，**无积分付费设计、无悬赏提问**。

### 3.2 第三方应用（OAuth2）

用户通过 OAuth2 授权后在第三方应用内消费 CHB：

- 消费必须实时回调数据库（幂等键防重），防止一份积分在多个应用重复使用。
- 每笔消费扣除 `手续费 = 消费金额 × 应用费率`（默认 10%，管理后台可配置）。
- 手续费进入官方积分池；扣除手续费后的净额进入应用绑定用户账户。
- 应用可设置最低授权等级，低于该等级的用户无法完成 OAuth2 授权登录。

### 3.3 集市消费

- 买家下单后扣除 CHB；手续费默认 10% 进入官方积分池；净额进入卖家账户。
- 订单幂等键保证同一订单不会被重复扣款。

## 4. 积分集市

### 4.1 入驻机制

- 用户提交入驻申请（店铺名称 + 描述）。
- 管理后台审核：通过 / 拒绝（可填写审核意见）。
- 审核通过后方可发布商品。

### 4.2 商品发布

- 商品状态流转：`pending`（待审核）→ `approved`（通过）/ `rejected`（拒绝）。
- 管理后台审核商品后用户才能下单。

### 4.3 交易流程

```
买家下单 → 校验商品可售 → 扣除买家余额 → 手续费入官方池 → 净额入卖家账户 → 生成订单记录
```

- 下单使用行级锁 + 乐观锁，防止超卖和余额并发问题。
- 订单状态：pending → completed / cancelled。

## 5. 手续费与官方积分池

- **默认手续费率：10%**，管理后台可配置。
- 所有手续费（应用消费 + 集市交易）进入官方积分池。
- 官方积分池是系统超级管理员的账户积分，用于运营支出。

## 6. 释放阀（通缩缓解机制）

### 6.1 设计原则

采用"逻辑隔绝 + 可控释放阀"策略：
- 公共池与官方池逻辑隔绝，正常情况下互不流通。
- 当公共池水位过低时，通过释放阀从官方池回补公共池。

### 6.2 释放操作

| 参数 | 说明 | 默认值 |
|------|------|--------|
| 自动释放启用 | 是否允许系统自动释放 | true |
| 释放阈值 | 公共池水位低于该百分比时触发 | 80% |
| 释放比例 | 每次释放的官方池余额比例 | 50% |
| 月度释放上限 | 每月自动释放总量上限 | 10,000,000 |

- 手动释放：管理后台输入金额 + 原因，执行即时释放。
- 自动释放：定时任务检测公共池水位，低于阈值时按比例释放。
- 所有释放操作记录到 `release_logs` 表，可审计。

## 7. 对账与审计

### 7.1 对账约束

```
守恒等式：用户余额总和 + 公共池余额 + 官方池余额 = 5 亿
```

### 7.2 审计日志

- 管理后台所有配置变更、审核操作、用户冻结/解冻、积分追回均写入 `audit_logs`。
- 所有交易写入 `transactions` 表（含幂等键、手续费、流向）。
- 所有奖励发放写入 `reward_logs` 表（含等级、倍率、IP）。

## 双积分体系：可用积分与未来积分

### 积分类型

| 类型 | 说明 | 来源 | 可消费 |
|------|------|------|--------|
| 可用积分 | 当前可自由支配的积分 | 论坛活跃奖励、未来积分到期转入 | 是 |
| 未来积分 | 暂时冻结的积分，不可消费 | 集市商品售卖收入（扣手续费后） | 否 |

### 转换规则

| 场景 | 处理方式 |
|------|---------|
| 订单完成，7天内无争议 | 未来积分 → 可用积分（第7天24:00自动转入） |
| 买家发起争议，卖家同意退款 | 未来积分 → 原路退回买家（含手续费） |
| 买家发起争议，卖家拒绝，管理员判买家胜 | 未来积分 → 原路退回买家（含手续费） |
| 买家发起争议，卖家拒绝，管理员判卖家胜 | 未来积分 → 48小时后自动转为可用积分 |
| 买家发起争议，卖家3天未处理 | 未来积分 → 原路退回买家（含手续费） |

### 退款规则

退款时买家获得全额返还（含手续费），卖家从未来积分扣减净额，官方池不收取该笔手续费。

## 集市争议退款流程

### 状态枚举

| 状态 | 含义 |
|------|------|
| pending | 买家已发起，等待卖家处理 |
| accepted | 卖家同意退款，已退款 |
| rejected | 卖家拒绝，等待管理员审核 |
| auto_refunded | 卖家超时未处理，自动退款 |
| admin_buyer_win | 管理员判定买家胜，已退款 |
| admin_seller_win | 管理员判定卖家胜，卖家未来积分48h后转可用 |
| closed | 争议关闭 |

### 定时任务

每天下午18:00 CST 执行：
1. 未来积分自动转入（7天到期且无争议）
2. 争议超时自动退款（3天未处理）
3. 卖家胜诉积分转入（48h后）

### 数据库变更

- `user_balances` 增加 `pending_balance` 字段
- `marketplace_orders` 增加 `dispute_status`、`pending_release_at`、`seller_pending_credited` 字段
- 新建 `disputes` 表（争议订单）
