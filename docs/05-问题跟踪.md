## P6 AdminAuth 不校验 key 值

**状态**：已验证

**问题描述**：中间件只检查 X-Admin-Key 头是否存在，不验证具体值。任何非空字符串都能通过。

**涉及文件**：
- `chb-backend/internal/middleware/auth.go` — AdminAuth 函数
- `chb-backend/config.yaml` 或环境变量 — 需配置合法 admin key

**修复方案**：AdminAuth 校验 key 值与配置中的 admin_key 是否一致。

## P12 新服务器部署问题（198.44.177.228）

**状态**：已验证

**背景**：旧部署服务器 112.213.106.104 不可达，迁移到新服务器 198.44.177.228，从零部署 CampusHub 全套服务。

### 部署问题与解决方案

| # | 问题 | 原因 | 解决方案 |
|---|------|------|----------|
| 1 | SSH host key 冲突 | 新服务器 IP 曾用于其他主机，known_hosts 中有旧 key | ssh-keygen -R 清除旧 key |
| 2 | SSH 公钥认证被禁用 | sshd_config 中 PubkeyAuthentication no | 用 paramiko 密码登录，改为 yes 后重启 sshd |
| 3 | PostgreSQL 端口 5432 被占用 | 宿主机已运行 PostgreSQL | Docker PostgreSQL 改用端口 5433，更新 config.prod.yaml |
| 4 | PostgreSQL 18 数据卷不兼容 | PG18 更改挂载路径，/var/lib/postgresql/data 不可用 | 删旧卷，挂载到 /var/lib/postgresql |
| 5 | Nginx 配置文件缺失 | dpkg 安装时配置文件带 .dpkg-new 后缀 | 重命名 .dpkg-new 为正确文件名 |
| 6 | Nginx 端口 80 被旧进程占用 | 旧 nginx master 进程未纳入 systemd 管理 | pkill -9 nginx，删 PID 文件，reset-failed 后 systemctl start |
| 7 | Nginx 配置 UTF-16 编码 | 仓库中 nginx.conf 为 UTF-16，乱码无法使用 | 重写为 ASCII/UTF-8 配置文件 |
| 8 | Go 版本低于 go.mod 要求 | go.mod 声明 go 1.25.0，安装的是 1.23.6 | 实际编译成功（Go 向前兼容），未阻塞 |
| 9 | PowerShell/SSH 引号嵌套 | JSON 和 SQL 通过 SSH 传输时引号被 shell 吃掉 | 用 paramiko、SCP 文件传输、heredoc 替代 |

**涉及文件**：
- ~/.ssh/config — devbox 指向更新为 198.44.177.228:22
- deploy/config.prod.yaml — 端口 5433、IP 更新
- deploy/systemd/chb-frontend.service — IP 更新
- /etc/nginx/sites-available/campushub — 重写的 Nginx 反向代理配置

**最终部署状态**：
- PostgreSQL 18 (Docker, 端口 5433)
- Go 后端 (端口 9090, systemd)
- Next.js 前端 (端口 3000, systemd)
- Nginx 反向代理 (端口 80)
- 外部访问 http://198.44.177.228 正常
- is_balanced: true (50亿 CHB)
- 全部服务开机自启

**备注**：Discourse 论坛容器尚未部署（需端口 9800），前端 Navbar 中论坛链接仍指向旧 IP。
