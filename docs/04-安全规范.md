# CampusHub 安全规范文档

> 创建时间：2026-08-13
> 本文档定义 CampusHub 项目的安全设计规范，涵盖认证、鉴权、数据保护、API 安全等。

## 1. 认证体系

### 1.1 OAuth2 IdP

CampusHub 后端作为 OAuth2 Identity Provider，支持授权码模式（Authorization Code）。

| 组件 | 说明 |
|------|------|
| 授权端点 | GET /oauth/authorize（前端页面） |
| 确认端点 | POST /api/oauth/authorize/confirm |
| Token 端点 | POST /oauth/token |
| 令牌校验 | POST /oauth/introspect |

### 1.2 鉴权方式

| 鉴权方式 | 请求头 | 适用场景 |
|---------|--------|---------|
| Bearer Token | Authorization: Bearer xxx | OAuth2 授权应用访问 |
| API Key | X-API-Key: xxx | 内部服务调用（Discourse 插件） |
| 管理后台 Key | X-Admin-Key: xxx | 管理后台 API |
| 用户 ID | X-User-ID: xxx | 开发/测试环境用户模拟 |

### 1.3 OAuth2 Scope

| Scope | 权限 | 敏感级别 |
|-------|------|---------|
| profile:read | 读取用户资料 | 低 |
| chb:read | 查询 CHB 余额 | 低 |
| chb:spend | 消费 CHB 积分 | 高 |

## 2. 积分安全

### 2.1 幂等控制

- 所有积分扣除操作必须携带 idempotency_key
- transactions 表 idempotency_key 字段唯一索引保证幂等
- reward_logs 表 (ref_type, ref_id, discourse_user_id) 唯一索引防止重复发奖

### 2.2 并发控制

- 用户余额更新使用行级锁（SELECT FOR UPDATE）+ 乐观锁（version 字段）
- 积分池更新使用行级锁，防止并发超扣
- 集市下单使用库存行级锁，防止超卖

### 2.3 积分池隔离

- 公共积分池与官方积分池逻辑隔绝
- 用户积分只能从公共池获取
- 官方池通过收取手续费获得收益
- 释放操作从官方池向公共池转账，需管理员权限

## 3. API 安全

### 3.1 CORS

- 仅允许配置的源访问
- 允许方法：GET, POST, PUT, DELETE, OPTIONS
- 允许头：Content-Type, Authorization, X-API-Key, X-Admin-Key, X-User-ID

### 3.2 速率限制

- 默认 100 请求/秒，突发 200
- 可在配置文件中调整

### 3.3 最低等级拦截

- OAuth2 应用创建时可配置 min_trust_level
- 授权确认时校验用户等级，低于最低等级则拒绝授权

## 4. 审计与合规

- 管理后台所有敏感操作写入 audit_logs
- 积分变动全部写入 transactions（含手续费、流向）
- 奖励发放全部写入 reward_logs（含等级、倍率）
- 审计接口 GET /api/chb/audit 实时校验积分平衡

## 5. 密钥管理

- admin_key 通过配置文件管理，不硬编码到源码
- OAuth2 client_secret 仅在创建时返回一次，不入列表接口
- JWT secret 通过配置文件管理
- 数据库密码通过环境变量或配置文件管理

## 6. 部署安全

- 不在服务器上直接编辑代码，仅从 Git 仓库拉取
- 不在服务器上运行开发服务器
- 数据库密码不硬编码到代码中
- 服务器禁止执行 git reset --hard
- 生产环境使用 HTTPS（待配置 SSL 证书）
